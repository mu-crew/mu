[Keep a Changelog](https://keepachangelog.com/). mu follows
[Semantic Versioning](https://semver.org/) from 1.0.0 onward.

## [Unreleased]

### Changed

- **Rex worker and delegate tabs are muted on spawn.** When `spawnAgent` opens a new Rex window for a worker or delegate (`MU_ORCHESTRATOR !== "1"`), it best-effort runs `rex do client.tab.mute muted=true window_id=<id>` so Rex does not chime/notify on every worker or delegate completion. Orchestrators (`mu orchestrate`) stay unmuted, and a missing Rex app client is ignored.

## [6.0.1] — 2026-11-28

### Fixed

- **Rex terminal detection now recognises `$REX_BLOCK`** (with `TERM_PROGRAM=rex`), not only the retired `$REX_SESSION`. Current Rex builds no longer set `$REX_SESSION`, so `insideRex()`, `currentSessionName()`, and the pi extension's `mu/role` OSC 7501 reporter silently fell back to tmux (vtmux) inside Rex panes (causing `mu_delegate`, `mu agent spawn`, and `mu doctor` to target tmux). `$REX_SESSION` stays as a fallback for older Rex builds.
- **Backend-agnostic CLI messages.** Replaced hardcoded `tmux` wording in `missingWorkstreamError` (`mux session mu-<ws>`), `resolveSelf`, `mu me`, `workstream.name_invalid`, `mu doctor`'s `name-case` remediation, and `NoMultiplexerError` / `mu doctor`'s missing-multiplexer hint.

### Added

- **A settle's transcript entry names the answers it showed.** The `mu-keep-driving` custom message now carries `details: { shown: [<call id>, …] }`, the same list the settle reports to the delegate side. A transcript reader (mural) can tell which delegate answers a settle delivered without parsing its text, so a report that quotes another call's answer header is no longer mistaken for a second delivery (mural upstream ask #15).

## [6.0.0] — 2026-11-28

Two first-class multiplexers. mu drives crews in tmux (vtmux) or Rex with the same verbs, and herdr is retired. Delegate answers settle reliably (their own lane), crew tags are visible and repairable, ops record an actor role, a running pi switches model with `mu agent model`, closes record the worktree landing, and a development build can no longer migrate your live DB. Breaking: herdr and its SDK exports are gone, `LogRow.workstreamName` changed meaning, and the DB's capture revision moves to 9 (mu 5.7 can no longer open it writable). Read [How to upgrade mu](docs/guide/upgrade.md) first.

### Added

- **Development builds no longer migrate or publish the live DB.** A mu running from a git checkout or worktree (a `.git` ancestor before any `node_modules`), or with `MU_DEV_BUILD=1`, refuses any schema, capture or settle-lane upgrade of the user's live DB: `this mu is a development build (<path>); it would migrate your live DB from … to …. Unset MU_DB_PATH and set MU_STATE_DIR to a scratch dir, or MU_ALLOW_MIGRATE=1.` (`DevBuildMigrationError`, exit 4, the file untouched). The guard keys on the resolved DB path, not on which variables are set: the default state dir's `mu.db` (from `HOME`/`XDG_STATE_HOME`) counts however it is reached, defaults, `MU_DB_PATH` or `MU_STATE_DIR`. mu pins `MU_DB_PATH` to that file in every pane it spawns, and it wins over `MU_STATE_DIR`, so a reviewer's `MU_STATE_DIR=$(mktemp -d)` alone never isolated a branch build: that is how the live DB was migrated twice on 2026-11-27. Opening an up-to-date live DB still works. Such a build also does not flush the live DB's ops into `MU_SYNC_DIR` (`DevBuildSyncError`: `mu sync` exits 4, the ambient flush warns on stderr and the verb carries on); the ops stay pending in `ops` and the installed mu publishes them. `MU_ALLOW_MIGRATE=1` lifts both. An installed package that is a symlink into a checkout (`npm link`) counts as a development build.
- `agent close` records the worktree's **landing** in its `agent.close` op, so a reader can check after the tree, its registry row and its pane are gone whether the work reached its target. The payload is JSON `{text, name, landing}`, where `text` is the prose `mu log` still prints. `landing` holds `repo_root`, `target_ref`, `base_sha`, `head_sha` and `preserved_ref`, the `mu/<ws>/<agent>-<sha12>` branch kept for unmerged commits. It is read before teardown and never from the pane. Local closes, orphan trees left by a reaped row, remote/mule/host closes and recovery closes all record it. A remote tree's `repo_root` is the checkout on its host and its `target_ref` is null. `landing` is null for a close with no tree. SDK: `readCloseLanding(listLogs row)` and `type Landing`, both exported. (mural upstream ask #9, fsj U2)
- `mu agent model <name> <provider>/<id> [--effort off|minimal|low|medium|high|xhigh|max] -w <ws>` switches a running pi agent's model, and with `--effort` its thinking level, over the control socket's new `model` op (pi's `setModel` / `setThinkingLevel`, never a typed `/model`; busy or idle, the running turn finishes on the old model). `--json` returns `{agent, workstream, transport, model, thinkingLevel, state}`. An agent off the ctl channel is refused with `AgentModelNeedsCtlError` (exit 2); pi refusing (unknown model, no auth) is `AgentModelRefusedError` (exit 1), model unchanged. The ctl `status` reply now carries `model` and `thinkingLevel` (and so does `ctlProbe`'s `status`); the SDK exports `setAgentModel` and `SetModelResult`; the switch logs an `agent.model` event. `ChannelDelivery.model` is optional (only ctl has it). An extension loaded before this answers `unknown op` (`AgentExtensionOutdatedError`): `/reload` it. (mural upstream ask #2)
- **Actor role:** every op now carries a nullable `actor_role`, `orchestrator`, `worker`, or `delegate` (`ops` and `op_ctx`, added in place; capture revision 7 → 8). Passive/system actors (`reaper`, `system`, `mu delegates prune`) and sessionless ops (`actor_session` null) always record `null`. Delegates (`MU_DELEGATE=1` set by `src/delegate-process.ts`, or a `delegate_calls` match) always record `delegate` and never become `orchestrator` or `worker` via a name clash. `MU_ORCHESTRATOR=1` records `orchestrator`; a managed agent registered in `agents` of the op's **target workstream** records `worker`; any other session issuing an orchestration intent (`task.add`, `agent.spawn`, `agent.send`, `agent.close`, `workstream.init`) records `orchestrator`; otherwise `null`. `withOpContext` takes `actorRole` and `workstream` (an explicit `actorSession` resolves for that session, not `process.env`); `listLogs()` rows and `currentOpContext()` expose `actorRole` (`null` on a read-only DB predating the column). New SDK read `listSessionRoles(db, { since? })` returns `{ actorSession, workstream, role, lastSeq }` per recorded triple in one aggregate query, no payloads read. The SDK also exports `resolveActorRole`, `resolveProvenance`, `ORCHESTRATION_INTENTS`, `SYSTEM_ACTORS`, `ResolveActorRoleInput` and `ActorRole`. **Compatibility:** the `CAPTURE_VERSION` 7 → 8 trigger upgrade means a DB opened writable by mu 6 cannot be reopened writable by mu 5.7 (mu 5.7 rejects it with `SchemaTooNewError`; read-only opens still work).
- **Crew tags are visible and repairable.** A spawn whose `@mu_*` pane tags fail to set keeps its pane but no longer stays silent: it prints one `warning: @mu_* tags not set on %N (tmux: <stderr>); murmur will show this agent as human; fix: mu agent retag` line, carries it in `--json` `warnings`, and a task-bound spawn records it in the new nullable `spawn_receipts.warning` column (kept across transitions; `SpawnReceipt.warning`, `SpawnedAgent.tagWarning`). `mu doctor` gains a `crew tags` row (`--json`: `environment.crewTags` with `warnings`): on tmux one `list-panes -a` per server reads every pane's `@mu_agent|@mu_workstream|@mu_role`, on Rex one block listing per session reads each block label (must be the agent's name) and its session label (must be `mu-<ws>`); it warns per live agent whose tags are missing or wrong. `mu agent retag [-w ws] [name...]` writes them again (tmux: the same guarded set-option; Rex: `session.set_block_label`), skipping panes already right, and reports `changed|ok|partial|failed` per agent (exit 1 on a failed write; a wrong Rex session label is reported `partial`, never renamed). It never writes a row it cannot prove owns the pane: `gone` (no live pane, or another tmux server's under the same id), `retired` (a herdr pane, never read as gone), `foreign` (another backend's pane), `unverified` (a legacy tmux row with no `pane_identity`, whose `%N` may be another server's: respawn it), `not_found` (a requested name with no row; exit 3). Doctor lists such legacy rows as `unverified` (`environment.crewTags.unverified`) instead of comparing them. `mu orchestrate` and plugin-view spawns surface the warning too. `MuxBackend` gains optional `readCrewTags` / `writeCrewTags`; `SpawnAgentPaneOptions.onTagFailure` reports the spawn's failure.

### Removed

- **BREAKING (semver-major, mu 6): the herdr backend.** mu drives tmux (vtmux or vanilla) and Rex only (spec 2026-11-27-rex-first-class §5). `src/mux/herdr.ts` is gone, and with it the SDK's `herdrBackend`, `HerdrError`, `HerdrSyntaxError`, `HerdrUnsupportedCliError`, `HerdrCommandOverrideError`, `HerdrWorkspaceGroupCloseError`, `isHerdrStatusUsable`, `setHerdrExecutor` and `resetHerdrExecutor`. `MuxBackendName` is `"rex" | "tmux"`. The herdr-only `MuxBackend` members go too: `spawnAgentWaitsReady`, `runsShellCommand`, `paneOccupied`, `reloadCommands`, `SpawnAgentPaneOptions.commandSource`, `SendOptions.readinessMs` and the `paste-vanished` send warning. `HostSpawnUnsupportedError` (only herdr raised it) is removed from the SDK, as is `viewRunning`'s `occupied` option and `AgentExtensionOutdatedError.recovery.muxReload`. `MU_MUX=herdr` now fails with a retirement message (exit 1); `$HERDR_ENV` and `MU_HERDR_SESSION` are no longer read.

### Changed

- **`mu task close --if-ready` refuses a rejected work blocker** (mural upstream ask #10, fsj U3): it exits 4 when a blocker is `CLOSED/rejected` and is not a finding. A finding (a task created with `--triage`) that is rejected counts as decided, as the findings recipe requires; `wontfix`, `duplicate` and `superseded` count as ready. Tasks carry a durable `finding` mark (new column `tasks.finding`, in the task's own op payload, so sync and `mu rebuild` agree; capture revision 8 -> 9; tasks from before it count as work). `--why -` and `--evidence -` read stdin like `--note -`; at most one of them may be `-`, and empty stdin is an error.
- New nullable column `worktrees.target_ref` (additive; machine-local, no capture change; schema stays v14): the full ref `--from` named, else the root's branch at spawn; null for a sha or a detached root.
- **pi extension, Rex:** a pi in a Rex terminal reports its crew role as an idle OSC 7501 record `id=mu/role` (title `orchestrator`, `worker` or `delegate`: `MU_DELEGATE=1` first, then `MU_ORCHESTRATOR=1`, then a managed agent), re-emitted on reload and cleared on exit; never in tmux (which has the `@mu_role` pane option) and never from a headless pi. It never outranks the agent's own record. murmur reads it so a Rex orchestrator that vanishes mid-work is recorded as crashed.
- **pi extension, tmux:** a pi sets the user pane option `@mu_pending` to the number of `mu_delegate` calls still owed to it, on its own pane (unset at 0, on exit and at start, so a killed predecessor's value goes). Only the pane's own interactive pi writes it (the one serving `MU_CTL_SOCK`, or one started outside mu); a nested or headless `pi -p`/json/rpc never does. Written only when `$TMUX`/`$TMUX_PANE` are well formed and the server's pid matches `$TMUX`; never on Rex. Consumers should trust it only while the pane reports OSC 7501 `working`. The OSC 7501 `mu/delegates` record is unchanged.
- **BREAKING (SDK): `LogRow.workstreamName` is the workstream**, the op key's part before the first `/` (`null` for machine-wide rows), from `listLogs` and `appendLog` alike; `LogRow.key` keeps the raw `ops.key`. Callers that read `workstreamName` as the key must read `key`. **`RenderableOp.workstreamName` is renamed `key`** (the input of `renderOp`, `renderOpLine` and `opSubject`).
- A row a herdr pane left (pane id `w1:p1`) stays recognised as a **retired backend** (`src/mux/binding.ts`): it is always foreign, so `reconcile` in full mode never reaps it as a ghost or reopens its task, `mu state` reports it `unknown` (`foreign backend: herdr`), and a spawn in its workstream refuses without offering `MU_MUX=herdr`. Every pane-addressed verb on such a row (`agent read`, `send`, `answer`, interrupt/abort, kill and pane probes) refuses with one `RetiredPaneError` (exit 5, `mux.retired_pane`) instead of reaching tmux or Rex with a foreign id. `mu agent close` without `--force` refuses the same way (no row or task touched); `--force` drops the row and reopens its tasks. `mu workstream teardown` keeps the row (`orphanedAgents` reason `retired`) instead of reading the pane as dead. `muxByName("herdr")` throws the retirement message. No state-directory change: the rows are kept as they are.
- `agent.send_unsupported` (a non-pi, non-hook CLI on tmux) points to Rex (`MU_MUX=rex`) instead of herdr.

### Fixed

- Upgrading a file that predates `tasks.finding` re-folds task rows from their ops, so findings synced by an older build read `finding=1`, matching `mu rebuild`.
- **Delegate answers reach the caller's transcript even when a shell `mu wait` takes them first** (mural upstream ask #11, fsj U4). pi's settle wait now runs as the **settle lane** (`MU_WAIT_SETTLE=1`, set only on its own child). It keeps its own delegate cursor (`settle|delegate:<ws>/<id>` in `wait_cursors`) and numbers its waits on its own `settle|<caller>` row in `wait_registrations`. So it and a shell `mu wait` of the same pi session each see every delegate answer once and never supersede each other. An answer stays owed to the transcript, and counted in `@mu_pending`, until a settle shows it. That holds across an interrupt (Esc in a tmux or Rex pane, `mu agent abort`, murmur stop's ctl path or its Escape fallback), including one in the wake's own turn, and across a reload. `mu delegates list --json` marks a done or failed call the lane still owes `settleOwed: true`, and the next pi runtime of the session re-adopts it. The first open of an existing DB adopts the lane once: every delegate answer an older mu consumed counts as shown. The mark is bit 1 of `PRAGMA user_version`. It is a header field, with no schema or capture change, so mu 5.7 still opens the file. SDK: `settleKey`, `settleOwed`, `adoptSettleLane`, `settleLaneAdopted` (src/wait-cursor.ts); `beginWait` / `endWait` take an optional `lane` (`"shell"` by default).
- Ops a mu pi extension runs (delegate register/finish, settle and close nudges, task verbs) now record the pi session and turn that ran them (`ops.actor_session`, `actor_anchor`): the extension passes `MU_ACTOR_SESSION` / `MU_ACTOR_ANCHOR`, since pi exports `PI_SESSION_ID` only to its bash tool. On those runs it unsets an inherited `PI_SESSION_ID` / `PI_SESSION_FILE`, so an unknown session or anchor records none, never a parent pi's. A spawned worker pane pins both empty (unset on a remote pane) and a mux-free delegate's child pi inherits none of the four, so a worker's or delegate's ops never credit its spawner. The pi extension bundle stays free of better-sqlite3 (`src/provenance-env.ts`), checked by a test. (mural upstream ask #8, fsj U1)
- tmux `killPane` is idempotent on a sessionless server (`exit-empty off`) too: `pane not found` and `no current target` read as gone, as in `paneAlive`, instead of throwing `TmuxError`. (release-review medium_mu_mux_tmux_killpane_throws)
- `AgentModelNeedsCtlError` suggests `mu agent spawn ... --model <provider/id> -w <ws>`; it used to put a command string in `--cli`, which `spawn` takes as a harness key. (release-review medium_mu_agents_model_agent_model_needs)
- A local worker pane (tmux and Rex alike) pins `MU_ORCHESTRATOR` (`1` only for `mu orchestrate`), `MU_DELEGATE`, `MU_REMOTE`, `MU_REMOTE_KEY`, `MU_AGENT`, `MU_HOST`, `MULE_PI_JOB_PREFIX` (set again for a mule job), `PI_SESSION_ID` and `PI_SESSION_FILE` empty. A tmux server born in a pi session (or a shell rc) no longer hands a worker its spawner's role (`mu_delegate`, `actor_role`) or pi session: an empty `MU_ACTOR_SESSION` fell through to `PI_SESSION_ID`, crediting the spawner for a claude/codex/cursor-agent/muse worker's ops. A remote transport pane also unsets `MU_DELEGATE`, `PI_SESSION_ID`, `PI_SESSION_FILE` and `MULE_PI_JOB_PREFIX`. (release-review high_mu_agents_spawn_local_tmux_workers)
- `mu agent reattach` sets the crew tags (`@mu_agent`, `@mu_workstream`, `@mu_role=worker`) on the new carrier or plugin view, as spawn does, so murmur no longer shows a reattached agent as a human pane and `mu doctor` no longer flags it until `mu agent retag`. A tag failure prints spawn's one `warning:` line and rides in `--json` as `tagWarning`. (release-review medium_mu_agents_reattach_lease_and)
- Every real tmux and rex CLI call is bounded (30 s), and spawn's `command -v` lookup too (5 s): a wedged server or a hanging config hook no longer hangs mu, or the strict agent/spawn lock it holds. A timed-out call is a `TmuxError` / `RexError` whose detail says `timed out after <ms>ms`, never read as a gone pane. (release-review medium_mu_mux_agents_unbounded_external)
- A row another live backend made (a Rex `block:` row under tmux, a tmux `%N` row under Rex) is no longer read as dead. Every pane probe and action on it refuses with `ForeignPaneError` (exit 5, `mux.foreign_pane`, naming `MU_MUX=<backend>`), where it used to answer "gone" without asking. `mu agent close` without `--force` refuses with `ForeignPaneError` before any side effect (a detached plugin job keeps running) and keeps the row, tree, channels and task. Before, it deleted them and reported the pane killed while the pane ran on. `--force` drops the row and reports `killedPane: false`: no kill is issued on another backend's pane. `send`, `fresh`, slash commands, interrupt/abort, `answer` and `--model` on such a row refuse with `ForeignPaneError` on every channel (ctl, hooks, mux), where a tmux row under Rex read as dead (`AgentPaneDeadError`: Rex's server identity never matches a tmux one) and a Rex row's `answer` under tmux read as not blocked (`AgentNotBlockedError`); Rex's per-pane state read reports such a row `unknown`, not gone. `mu workstream teardown` keeps the row (`orphanedAgents` reason `foreign`) instead of reaping it and reopening its task, a host channel's reclaim keeps it, a gate reads it `unknown`, and ctl delivery never calls it dead. `agent attach` on a retired herdr row now gives `RetiredPaneError` and its remedy, not a backend mismatch. (release-review high_mu_mux_agents_foreign_backend_panes, low nit 1)
- Small mux/close fixes. `closeAgent`'s `killedPane` is true only when a kill was issued: a retired herdr row, a pending placeholder or a mux-less `--force` close reports `false`. Rex `sendToPane` refuses a bare `\r` without bracketed paste, as it already did a newline, since a CR also submits early. A Rex screen capture (`lines: 0`) of a block reporting 0 rows reads the detached size, not the whole scrollback. (release-review low_mu_mux_agents_batched_minor_nits 2, 3, 5)
- tmux pane reads that skipped the server fence now apply it. `paneStatus` takes a verified pane ref, so vtmux's OSC 7501 status (`mu state`, the hooks send gate's murmur-less fallback) is read only on the row's recorded server: a recycled `%N` on a restarted server reports nothing. ctl delivery's dead-pane check and the hooks first-prompt check also pass the row's `paneIdentity`. `MuxBackend.paneStatus` accepts `string | VerifiedPaneRef`. (release-review medium_mu_mux_channels_unverified_tmux)
