## Findings and verdicts

Verdicts are mine, from reading each test and profiling it. None is a
MERGE or DELETE, so no refuter was needed (step 3). Each SPEED-UP was
checked to still fail on the bug it guards where a cheap mutant exists.

### Rejected / not done

- **Moving the 33 non-tmux `*.integration.test.ts` files to the fast tier.**
  Together ~19 s serial (db-wal-race 4.1 s, cli-sync 3.7 s and sync-session
  2.1 s are most of it; those spawn subprocesses and stay). The rest, ~9 s of
  `runCli` tests, would add ~1 s to the fast gate in parallel; the repo rule
  names the split by real tmux/herdr/VCS/subprocess use. Not a clear win: KEEP.
- **Dropping the `legacy_alter_table` trick for a real DROP COLUMN.** The test
  only needs the old column set on disk; the stored trigger SQL is unchanged by
  the pragma (the mutant above still fails the test).
